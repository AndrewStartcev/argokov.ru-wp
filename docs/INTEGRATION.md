# Argokov — правила интеграции WordPress

Тема интегрируется по тем же правилам, что и RoverLand-wp.

## Базовый принцип

1. Сначала сохраняем HTML-структуру и BEM-классы исходной верстки 1:1.
2. После визуального совпадения заменяем только контентные значения на WordPress/ACF.
3. Общие сущности выносим в CPT/таксономии только когда подтверждена повторяемость.
4. Служебная PHP-логика хранится в `functions/`, общие части — в `template-parts/`, ACF Local JSON — в `acf-json/`.

## ACF

- H1 и H2 — обычные text-поля.
- WYSIWYG — только для контента с обычными HTML-тегами без дизайн-классов.
- Карточки, иконки, ссылки, повторяющиеся элементы и параметры — структурные поля ACF.
- Размеченные дизайн-блоки в WYSIWYG не складываем.
- Все группы полей сохраняем в `acf-json`.

## Этапы

1. Статическая вёрстка → WordPress-шаблоны.
2. Общая шапка, подвал и ассеты.
3. Настройки сайта и меню.
4. ACF по отдельным шаблонам.
5. Динамические материалы и кейсы.
6. Формы, SEO и финальная проверка.


## Используемые плагины

На проекте используются следующие плагины:

- Advanced Custom Fields PRO — поля и ACF Local JSON.
- Advanced Custom Fields: Theme Code Pro — вспомогательный инструмент для работы с ACF-полями.
- Contact Form 7 — формы обратной связи.
- Cyr-To-Lat — транслитерация slug/URL.
- Rank Math SEO — SEO-метаданные, sitemap и связанные SEO-настройки.
- WP Rocket — кэширование и оптимизация производительности.
- Редактор кода — файловый менеджер/редактор кода в админке.

При интеграции не дублируем функциональность этих плагинов собственными решениями без необходимости. Для полей используем ACF PRO, формы строим через Contact Form 7, SEO оставляем Rank Math.


## Админка WordPress

Админка должна содержать только сущности и инструменты, которые реально используются проектом.

Скрываем/отключаем:

- стандартные «Записи» — статьи живут в CPT `material`;
- Gutenberg, block patterns, block widgets и их frontend CSS;
- Site Editor, Font Library, Widgets и Customizer;
- встроенные редакторы файлов тем и плагинов;
- Quick Draft, WordPress Events/News и welcome panel;
- комментарии и trackbacks у страниц и кейсов;
- WordPress generator, shortlink, WLW/RSD, лишние oEmbed/REST discovery ссылки;
- Emoji assets;
- XML-RPC.

Сохраняем:

- Страницы;
- Материалы;
- Кейсы;
- Комментарии для материалов;
- Медиафайлы;
- меню;
- ACF/настройки «Аргоков»;
- Rank Math SEO;
- Contact Form 7;
- системные обновления и Site Health.

## SEO и AI-ready архитектура

- Весь индексируемый контент выводится сервером в HTML; значимый текст не зависит от выполнения JavaScript.
- На каждой индексируемой странице один логический H1, далее корректная иерархия H2/H3.
- Ссылки и навигация — обычные `<a href>`, доступные краулерам без JS.
- Title, description, canonical, robots, Open Graph, sitemap и базовую SEO-схему контролирует Rank Math; тема не должна дублировать их.
- Schema.org добавляем только для реально существующих сущностей и видимого контента: Organization/Person, Service, Article, BreadcrumbList, FAQPage и другие типы по назначению.
- Для материалов обязательны автор, дата публикации, дата обновления, рубрика/тематика и понятная связь с услугами/другими материалами.
- Для изображений используем содержательные alt, реальные width/height и подходящие форматы; декоративные изображения не должны создавать SEO-шум.
- URL короткие, стабильные и человекочитаемые; редиректы только 301 при реальном изменении адреса.
- Внутренняя перелинковка строится между услугами, кейсами, материалами и страницами экспертизы.
- Не добавляем «AI SEO» хаки и дублирующие метатеги без подтверждённой пользы. Приоритет — чистый HTML, сущности, авторство, структурированные данные и качественный индексируемый контент.


## Главная страница

Главная интегрирована через `front-page.php` и секции в `template-parts/home/`.

Правила:

- весь текст и повторяемые элементы секций управляются через ACF;
- H1/H2 хранятся в text-полях;
- повторяемые карточки, списки, этапы и FAQ — repeater;
- вводный текст сложных проектов допускает WYSIWYG, потому что внутри только обычные контентные теги без дизайн-классов;
- глобальные данные основателя, контакты и основная форма берутся из настроек «Аргоков»;
- кейсы и материалы не дублируются на главной: они выбираются relationship-полями из CPT `case` и `material`;
- при отсутствии выбранных записей используется исходный контент верстки как безопасный fallback;
- Contact Form 7 подключается через глобальное поле shortcode; пока shortcode не задан, сохраняется исходная HTML-форма;
- Schema.org на главной намеренно отсутствует. Structured data будет отдельным модулем после отдельного проектирования.


## Базовое наполнение

Исходный контент хранится в `data/base-content.json`.

`functions/base-content.php` выполняет одноразовое автоматическое наполнение после обновления темы при первом административном запросе, когда активен ACF PRO.

Начальное наполнение:

- создаёт или использует текущую страницу «Главная» и назначает её статической главной;
- заполняет ACF главной;
- создаёт 2 базовых кейса;
- создаёт 3 базовых материала;
- связывает кейсы и материалы с главной через relationship;
- заполняет базовые глобальные данные, если они пустые;
- записывает Title и Description главной в Rank Math, если они ещё не заполнены;
- не перезаписывает уже заполненные ACF-поля.

Версия выполненного наполнения хранится в option `argokov_base_content_seed_version`. Для будущего управляемого повторного запуска нужно увеличить `version` в `data/base-content.json`.

Schema.org импортёр не создаёт и не настраивает.


## Текущая архитектура контента

Интегрированы и автоматически наполняются:

- Главная — `front-page.php` + `template-parts/home/*`;
- О студии — `page-about.php`;
- Услуги — `page-services.php`;
- Разработка — `page-development.php`;
- Поддержка — `page-support.php`;
- Как работаем — `page-process.php`;
- FAQ — `page-faq.php`;
- Контакты — `page-contacts.php`;
- Реквизиты — `page-requisites.php`;
- Политика обработки ПДн, согласие и cookie — обычный `post_content` через общий юридический шаблон;
- Кейсы — CPT `case`, динамический архив и `single-case.php`;
- Статьи — CPT `material`, динамический архив и `single-material.php`.

Для страниц с уникальным дизайном контент хранится в структурных ACF-полях. Юридические документы хранятся в обычном редакционном содержимом WordPress, потому что им не нужна дизайн-структура из repeater-полей.

## Материалы

Статья не хранит дизайн-классы внутри WYSIWYG. Для тела материала используется ACF Flexible Content с ограниченным набором редакционных блоков:

- вводный абзац;
- выделенный callout;
- раздел с H2 и обычным WYSIWYG-контентом;
- чек-лист;
- блок кода;
- карточки ошибок/ситуаций;
- итоговый CTA.

Содержание статьи строится автоматически из H2-разделов. Автор, даты, время чтения, обложка и связанные материалы выводятся сервером.

Комментарии работают через штатную систему WordPress только у материалов. Для анонимного комментария обязательно согласие на обработку персональных данных; комментарии проходят стандартную модерацию WordPress.

Schema.org в материалах и комментариях сейчас намеренно отсутствует.

## Формы

На сайте используется одна основная Contact Form 7.

Если поле `site_contact_form_shortcode` пустое и Contact Form 7 активен, тема один раз создаёт форму «Основная форма — Аргоков» и записывает shortcode в глобальные настройки.

Эта форма используется:

- на главной;
- на странице разработки;
- на странице поддержки;
- на странице контактов;
- в материалах;
- в общей модальной форме.

Модальная форма находится в HTML страницы и открывается JavaScript только как интерфейс. JavaScript больше не создаёт отдельную декоративную форму.

Если Contact Form 7 недоступен, вместо неработающей формы показываются телефон и email.

## Автоматическое начальное наполнение

`data/base-content.json` — единственный источник первоначальных данных темы.

Seeder:

- не перезаписывает непустые ACF-поля;
- не перезаписывает уже заполненные Title/Description Rank Math;
- создаёт страницы и назначает им шаблоны;
- создаёт и назначает WordPress-меню;
- создаёт кейсы и материалы;
- открывает комментарии у материалов;
- назначает страницу политики конфиденциальности в настройках WordPress;
- назначает статическую главную;
- заполняет связи с кейсами и материалами;
- безопасно запускается повторно только после увеличения версии JSON.

После первоначального наполнения контент редактируется из WordPress, а не из JSON.

## Structured data

Schema.org не добавляем автоматически на текущем этапе.

Отдельный модуль структурированных данных будет проектироваться после окончательного утверждения контентной модели. До этого тема не должна выводить `itemscope`, `itemprop`, JSON-LD или дублировать Schema Rank Math.


## Архитектура услуг

Услуги строятся как иерархия WordPress Pages, чтобы можно было создавать десятки и сотни отдельных SEO-посадочных без отдельного CPT и кастомной permalink-логики.

Базовая структура:

- `/services/` — общий каталог услуг;
- `/services/development/` — направление «Разработка»;
- `/services/support/` — направление «Поддержка»;
- конкретные услуги — дочерние страницы соответствующего направления, например:
  - `/services/development/corporate-sites/`;
  - `/services/development/internet-shops/`;
  - `/services/development/web-services/`;
  - `/services/development/technical-seo/`;
  - `/services/development/integrations/`;
  - `/services/support/one-time-improvement/`;
  - `/services/support/project-takeover/`.

Для конкретных услуг используется `page-service-detail.php` + ACF-группа `group_argokov_service_detail`.

«Разработка» и «Поддержка» не являются отдельными пунктами верхнего уровня меню: они вложены в «Услуги». Старые адреса `/development/` и `/support/` перенаправляются 301 на новые вложенные URL.

На главной карточки основных направлений ведут на реальные страницы направлений. В подвале ссылки услуг ведут на реальные URL без якорей-заглушек.
