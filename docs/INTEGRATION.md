# Argokov — правила интеграции WordPress

Тема интегрируется по тем же правилам, что и RoverLand-wp.

## Базовый принцип

1. Сначала сохраняем HTML-структуру и BEM-классы исходной верстки 1:1.
2. После визуального совпадения заменяем только контентные значения на WordPress/ACF.
3. Общие сущности выносим в CPT/таксономии только когда подтверждена повторяемость.
4. Служебная PHP-логика хранится в `functions/`, общие части — в `template-parts/`, ACF Local JSON — в `acf-json/`.

## ACF

- H1 и H2 — обычные text-поля.
- WYSIWYG — только для контента с обычными HTML-тегами без дизайн-классов.
- Карточки, иконки, ссылки, повторяющиеся элементы и параметры — структурные поля ACF.
- Размеченные дизайн-блоки в WYSIWYG не складываем.
- Все группы полей сохраняем в `acf-json`.

## Этапы

1. Статическая вёрстка → WordPress-шаблоны.
2. Общая шапка, подвал и ассеты.
3. Настройки сайта и меню.
4. ACF по отдельным шаблонам.
5. Динамические материалы и кейсы.
6. Формы, SEO и финальная проверка.


## Используемые плагины

На проекте используются следующие плагины:

- Advanced Custom Fields PRO — поля и ACF Local JSON.
- Advanced Custom Fields: Theme Code Pro — вспомогательный инструмент для работы с ACF-полями.
- Contact Form 7 — формы обратной связи.
- Cyr-To-Lat — транслитерация slug/URL.
- Rank Math SEO — SEO-метаданные, sitemap и связанные SEO-настройки.
- WP Rocket — кэширование и оптимизация производительности.
- Редактор кода — файловый менеджер/редактор кода в админке.

При интеграции не дублируем функциональность этих плагинов собственными решениями без необходимости. Для полей используем ACF PRO, формы строим через Contact Form 7, SEO оставляем Rank Math.


## Админка WordPress

Админка должна содержать только сущности и инструменты, которые реально используются проектом.

Скрываем/отключаем:

- стандартные «Записи» — статьи живут в CPT `material`;
- Gutenberg, block patterns, block widgets и их frontend CSS;
- Site Editor, Font Library, Widgets и Customizer;
- встроенные редакторы файлов тем и плагинов;
- Quick Draft, WordPress Events/News и welcome panel;
- комментарии и trackbacks у страниц и кейсов;
- WordPress generator, shortlink, WLW/RSD, лишние oEmbed/REST discovery ссылки;
- Emoji assets;
- XML-RPC.

Сохраняем:

- Страницы;
- Материалы;
- Кейсы;
- Комментарии для материалов;
- Медиафайлы;
- меню;
- ACF/настройки «Аргоков»;
- Rank Math SEO;
- Contact Form 7;
- системные обновления и Site Health.

## SEO и AI-ready архитектура

- Весь индексируемый контент выводится сервером в HTML; значимый текст не зависит от выполнения JavaScript.
- На каждой индексируемой странице один логический H1, далее корректная иерархия H2/H3.
- Ссылки и навигация — обычные `<a href>`, доступные краулерам без JS.
- Title, description, canonical, robots, Open Graph, sitemap и базовую SEO-схему контролирует Rank Math; тема не должна дублировать их.
- Schema.org добавляем только для реально существующих сущностей и видимого контента: Organization/Person, Service, Article, BreadcrumbList, FAQPage и другие типы по назначению.
- Для материалов обязательны автор, дата публикации, дата обновления, рубрика/тематика и понятная связь с услугами/другими материалами.
- Для изображений используем содержательные alt, реальные width/height и подходящие форматы; декоративные изображения не должны создавать SEO-шум.
- URL короткие, стабильные и человекочитаемые; редиректы только 301 при реальном изменении адреса.
- Внутренняя перелинковка строится между услугами, кейсами, материалами и страницами экспертизы.
- Не добавляем «AI SEO» хаки и дублирующие метатеги без подтверждённой пользы. Приоритет — чистый HTML, сущности, авторство, структурированные данные и качественный индексируемый контент.


## Главная страница

Главная интегрирована через `front-page.php` и секции в `template-parts/home/`.

Правила:

- весь текст и повторяемые элементы секций управляются через ACF;
- H1/H2 хранятся в text-полях;
- повторяемые карточки, списки, этапы и FAQ — repeater;
- вводный текст сложных проектов допускает WYSIWYG, потому что внутри только обычные контентные теги без дизайн-классов;
- глобальные данные основателя, контакты и основная форма берутся из настроек «Аргоков»;
- кейсы и материалы не дублируются на главной: они выбираются relationship-полями из CPT `case` и `material`;
- при отсутствии выбранных записей используется исходный контент верстки как безопасный fallback;
- Contact Form 7 подключается через глобальное поле shortcode; пока shortcode не задан, сохраняется исходная HTML-форма;
- Schema.org на главной намеренно отсутствует. Structured data будет отдельным модулем после отдельного проектирования.
